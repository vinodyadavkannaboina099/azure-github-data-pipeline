# Azure backend setup

This backend keeps the portfolio inexpensive and demonstrates a real Azure data pipeline:

`GitHub REST API -> Azure Data Factory -> ADLS Gen2 -> Azure Function -> Portfolio website`

## 1. Create ADLS Gen2

1. In Azure Portal, create a **Storage account**.
2. On the Advanced tab, enable **Hierarchical namespace**.
3. Create a container/file system named `portfolio`.
4. The pipeline writes GitHub data to `raw/github/repos.json`.

## 2. Create Azure Data Factory

1. Create a Data Factory and enable its system-assigned managed identity.
2. Give that identity the **Storage Blob Data Contributor** role on the storage account.
3. In ADF Studio, create/import the resources from `adf` in this order:
   - `linkedService_github.json`
   - `linkedService_adls.json`
   - `dataset_github_repos.json`
   - `dataset_adls_json.json`
   - `pipeline_github_to_adls.json`
   - `trigger_daily.json`
4. Replace `YOUR_STORAGE_ACCOUNT` in `dataset_adls_json.json`.
5. Debug the pipeline once and confirm that `portfolio/raw/github/repos.json` exists.
6. Publish and start the daily trigger.

## 3. Create the Azure Function backend

1. Create a Node.js 22 Azure Function App using the Flex Consumption plan.
2. Enable its system-assigned managed identity.
3. Give the identity **Storage Blob Data Reader** on the storage account.
4. Add these Function App environment variables:

   - `AZURE_STORAGE_ACCOUNT_URL=https://YOUR_STORAGE_ACCOUNT.blob.core.windows.net`
   - `PORTFOLIO_CONTAINER=portfolio`
   - `PROJECTS_BLOB=raw/github/repos.json`

5. Open the `api` directory in VS Code and run:

   ```bash
   npm install
   npm run build
   ```

6. Use the Azure Functions VS Code extension to deploy the `api` directory.
7. Test:

   - `https://YOUR_FUNCTION_APP.azurewebsites.net/api/health`
   - `https://YOUR_FUNCTION_APP.azurewebsites.net/api/projects`

## 4. Connect it to Azure Static Web Apps

For the simplest deployment, add this to the workflow generated by Azure Static Web Apps:

```yaml
app_location: "/"
api_location: "api"
output_location: ""
```

Static Web Apps then exposes the backend to the website as `/api/projects`.

## 5. Recommended first test

Run the ADF pipeline manually, open `/api/projects`, and confirm that the JSON contains your newest non-fork GitHub repositories. Only after that should the website call the endpoint.

## 6. Show the projects on the website

The optional website component is kept in `frontend/LiveProjects.tsx`. Copy it into a website only when you are ready to connect that site to this separate backend.

Suggested CSS:

```css
.live-project-grid { display: grid; grid-template-columns: repeat(2, 1fr); gap: 16px; }
.live-project { display: flex; flex-direction: column; gap: 12px; padding: 26px; background: white; border-radius: 24px; }
.live-project a { margin-top: auto; font-weight: 800; }
@media (max-width: 680px) { .live-project-grid { grid-template-columns: 1fr; } }
```
